problem: >-
  Ask a research tree what the current learning rate is and generic RAG quotes
  the archived config that still says 1e-5. Files sprawl across live configs,
  superseded drafts, Slurm logs and checkpoints, and filename search cannot
  tell which copy is the one that still counts.
approach: >-
  Rebuilt retrieval as a measured stack rather than a one-shot top-k. BM25 and
  dense search over pgvector fuse with reciprocal rank fusion at k=60, retrieve
  50, rerank 8. A forty-line router skips embedding and reranking on exact-path
  and aggregation queries. A staleness tier drops superseded versions before
  answering, and typed personalized PageRank fuses ranks for multi-hop
  questions. Retrieval sits inside an agent loop that grades its own results
  and rewrites weak queries, exposed as an MCP filesystem where every mutation
  returns a plan a human has to approve.
result: >-
  Recall@50 0.938 and nDCG@10 0.493 on a frozen 136-question gold set over a
  61-file tree, no LLM judge. The router lifts exact-path nDCG@10 from 0.596 to
  0.938. Blind graph expansion stays in the table as the loser: recall 0.986,
  nDCG 0.446, six times the wall clock.

## Where it goes next

The gold set is 136 questions over a 61-file demo tree. The next step is
swapping that for a real capstone directory — thousands of files, where the
staleness problem is genuinely adversarial — and re-running the same benchmark
rather than a new one.

ColPali-style page-image retrieval is the other open lane: the PDFs in a
research tree carry their results in figures and tables that text extraction
destroys.
